## 3. 关键缺陷与陷阱（每条附证据）

1. **同一化合物两个 DRUG_ID（标签泄漏 + 标签自相矛盾）**：9 个化合物各 2 个 ID，共 6,288 个重叠 (细胞系, 化合物) 对（占 2.60% 行）；同一细胞系两 ID 的 LN_IC50 差 \|Δ\| 中位 1.10、p90 2.93、最大 8.98，54.1% 的重复对 \|Δ\|>1。若按 DRUG_ID 做 LDO/统计，同一化合物会同时出现在训练与测试（泄漏），且同一对 (细胞系,化合物) 有两条矛盾标签（Dactinomycin 均值差 +2.37、Docetaxel −2.22）。
2. **Z_SCORE 的真实定义是"药内 z-score"而非全局 z**：Z_SCORE 与按 DRUG_ID 分组计算的 `(LN_IC50-mean)/std(ddof=1)` 的 max\|diff\|=1.18e-06（每药均值≈0、sd≈1）；与全局 z 相关仅 0.509。计划书 §3.3-7 想要的"药物内 z-score 主训练标签"**可直接用现成 Z_SCORE 列**（敏感分数 s = −Z_SCORE），但必须知道它按 DRUG_ID 计算，化合物级去重后需重算。
3. **AUC 方向与计划书口径冲突**：实测 corr(LN_IC50, AUC)=+0.763（Spearman +0.757）→ GDSC 的 **AUC 越大越耐药**；计划书 §3.3-7 中"CTRPv2 用 AUC（方向统一为越大越敏感）"不可套用到 GDSC。且 AUC 与 LN_IC50 高度相关（同一曲线派生的两个指标，不是独立标签），AUC 中位 0.944、p25–p75 0.849–0.975 存在【天花板效应】，直接回归会被压缩。
4. **LN_IC50 大面积外推/右删失**：71.81% 的曲线 LN_IC50 ≥ ln(MAX_CONC)（IC50 落在最高测试剂量之上，靠 NLME 外推）；仅 0.31% 低于最低剂量。板型 27 种 MAX_CONC（0.01–2000 µM），0.01–10 µM 板型占 53.1% → 不同药/不同板的 LN_IC50 不可直接跨药比较；|LN_IC50|>8 有 2,840 行（1.17%），极端如 ascorbate 13.82。
5. **覆盖稀疏且不均**：密度 84.67%；每药最少 225 株（5 个药）、14 个药 <300 株；每株药物数中位 279（=95% 药量），但 RH-18 仅 12、HCC202 仅 14 个药 → 这两株不能参与 LCO 训练/评估排序。
6. **药物标识缺口**：295 药中 InChIKey 242（82.0%）、ChEMBL 198（67.1%）、靶点 257（87.1%）、三者皆无 21（7.1%）；**SMILES 0/295**（两文件均无 SMILES 列、RDKit 未装、本地 dgidb 无 SMILES）→ GIN/Graphormer 药物图与 Morgan FP 在离线环境不可得，须外部拉取；13 个纯数字名药的"名称"疑似 PubChem CID（可作 SMILES 检索键）。
7. **标签靶点字段与元数据不一致 1 例**：标签 `PUTATIVE_TARGET` 行级缺失 11.52%（39 药全缺）vs 元数据 TARGET 缺 38 药，差集恰为 **DRUG_ID 1802**（标签空、元数据有）；其余 256 药靶点文本规范化后 0 差异。靶点覆盖应直接以元数据 TARGET 为准，标签列只作行级冗余。
8. **细胞系 ID 交叉的三处陷阱**：① Model.csv `SIDM00117` 一码两株（NCI-H322/NCI-H322M），GDSC2 侧是 NCI-H322M，须用 COSMICID 905967 仲裁；② RH-1（SIDM00427）在 Model.csv 完全无记录 → 969 株里唯一无法映射；③ Cell_Lines_Details.xlsx 与 Model.csv 的 COSMIC 只交集 976/1001（两表不同版），xlsx 仅可作 fallback 且需按 932/969（精确名）预期覆盖率。
9. **"8.5 药物元数据"实为 8.4 派生**：`screened_compounds_rel_8.4.csv`（2022-07-24）与 `screened_compounds_rel_8.5_inchi.csv` 的 DRUG_ID 集完全相同、name/target/pathway 零差异；后者只多了 CHEMBL_ID/INCHI_KEY（且 204/120 缺失）。本地没有官方 8.5 screened_compounds，**没有 SMILES**，也没有 8.5 新增字段。
10. **CANCER_TYPE 分组噪声**：42 个 GDSC 癌种 vs Model.csv 28 个 OncotreeLineage；`Other Solid Cancers`（6,998 行）主导 lineage 仅 25.8%、Non-Cancerous（7 株/1,949 行）主导仅 42.9%。用 CANCER_TYPE 做 LTO/分层会掺入跨组织样本；建议以 OncotreeLineage/OncotreePrimaryDisease 为分层主键，CANCER_TYPE 仅作兼容列。

## 4. 对数据预处理的影响（逐条给建议口径）

1. **化合物口径冻结**：建派生映射表 `DRUG_ID(295) → compound_key(286)`，键优先级 InChIKey > 标准化药名；9 对双 ID 化合物在 (细胞系, 化合物) 上合并：建议保留屏幕覆盖更大者（1911/1007/1200/1627/1089/1062/1908/1553/1803）或对重叠对取均值，并把"两 ID 标签差"记录为质量标记；合并后 235,748 对、密度 85.07%。**所有 LDO/化合物级分组、药物统计、标签归一化都以 compound_key 为组**。
2. **主标签用 Z_SCORE（药物内 z-score）**：直接使用现成 Z_SCORE（已证 = 药内 z(LN_IC50)），敏感分数 s=−Z_SCORE；若先做步骤 1 的化合物合并，则在合并后的 (细胞系, 化合物) 上重算 z（当前 Z 按 DRUG_ID 各自标准化，9 对药内部口径不一致）。原始 LN_IC50 与 AUC 仅作报告/辅助目标。
3. **LN_IC50 不设固定阈值**：86.1% 为正、分布近对称于 3.2；无物理零点。二分类一律用**药物内分位数**（median / tertile），295/295 药 n≥100（min 225）可支撑；阈值在 fold 内估计，避免泄漏。
4. **删/标记异常标签**：|Z|>3（约 0.3%）、RMSE>p99（0.215）且 LN_IC50 外推（≥ln MAX_CONC）的样本做敏感性分析；不做硬截断（截断会与 AUC 天花板叠加扭曲排序）。AUC 若用，先 logit 变换并统一方向为"敏感=大"（取 −AUC）。
5. **剔除 Non-Cancerous 7 株 / 1,949 行**；血液/淋巴相关 163 株 / 41,166 行（17.0%）单独评估或只在 LCO 内分层，避免组织域差主导指标。
6. **细胞系主键统一到 DepMap**：Model.csv `SangerModelID` 直连 967/969 + 名称兜底 1（NCI-H748）→ 968/969；RH-1 标注排除；SIDM00117 用 COSMICID=905967 仲裁到 ACH-002172；保留 `(DRUG_ID, CELL_LINE_NAME, SANGER_MODEL_ID)` 三键派生表供组学 join。xlsx 仅作 TCGA 标签 fallback（826/1,002 非空）。
7. **药物特征分层降级**：有 InChIKey 的 233 化合物 → 可做 scaffold/图（需外部 SMILES）；仅 ChEMBL 的补 198 药；21 个"三无"药用名称+靶点文本/DRUG_ID 占位并置 mask；靶点 multi-hot 用元数据 TARGET 257 药（去掉 38 缺失），标签文件列不重复采集。
8. **稀疏药/株不进主评估**：14 个 <300 株的药在 LDO 中单药指标方差大，报告时标注 n；RH-18/HCC202 不进 LCO。
