## 3. Git 策略

### 3.1 忽略规则（.gitignore）

| 路径 | 原因 | 保留 |
|---|---|---|
| `data/raw/*` | 8.3 GB 原始数据 + 许可限制 | `.gitkeep`、`README.md`、`CHECKSUMS.md5` |
| `data/interim/*` | 可由 raw 重新生成 | `.gitkeep` |
| `experiments/*` | 实验输出/日志/中间权重 | `.gitkeep`、`README.md` |
| `.venv/`、`.cache/` 等 | Python/uv 本地环境 | — |
| `configs/local/`、`.env*` | 机器相关/私有配置 | `.env.example` |
| `deploy/server/var/`、`*.db` | 部署运行时数据 | — |

> 说明：`data/raw/README.md` 与 `CHECKSUMS.md5` 属于小型元数据（数据索引与校验和），
> 不属于原始数据本体，因此从忽略中显式放行，保证数据可追溯（计划书 §3.8 要求记录
> URL/版本/日期/SHA256）。如团队认为应整体忽略，只需删除两条 `!` 放行规则。

### 3.2 Git LFS（.gitattributes）

- 目录级：`data/processed/**`、`data/splits/**`、`deploy/packages/**`
- 扩展名级兜底：`*.pt`、`*.pth`、`*.ckpt`、`*.safetensors`、`*.onnx`、`*.npz`、`*.npy`、
  `*.parquet`、`*.h5`、`*.hdf5`
- `**/.gitkeep` 最后匹配并显式排除出 LFS，避免占位文件变成 LFS 指针
- 文本统一 LF（`* text=auto eol=lf`），Windows 批处理保留 CRLF

**首次使用**：每台机器 `git lfs install`；clone 后 `git lfs pull`。
当前开发机未安装 git-lfs（`git: 'lfs' is not a git command`），需先安装再提交 LFS 文件。

## 4. 环境策略（详见 ADR-0002 与 `docs/environment.md`）

- **Python 3.12**（`.python-version`），包管理 **uv**（`pyproject.toml` + `uv.lock`）。
- **CUDA 12.6**：PyTorch 从 cu126 专用索引安装，`torch==2.14.1`（该索引上最新且有
  Windows/Linux cp312 wheel；2.15.0 未发布 cu126 构建）。NVIDIA 驱动需 **R560+**。
- 只支持 **Windows + Linux**（`[tool.uv] environments`）；macOS 暂不支持（无 cu126 wheel）。
- extras 分组：`train`（torch）、`graph`（PyG/RDKit）、`explain`（captum/SHAP/gseapy）、
  `deploy`（ONNX/onnxruntime）、`clinical`（lifelines/scikit-survival）；`dev` 依赖组含 pytest/ruff/mypy/pre-commit。
- 部署服务器 **不共用**主环境：`deploy/server` 自带独立 `pyproject.toml` + `.venv`，
  只装 fastapi/uvicorn 等轻量依赖，避免把服务依赖装进训练环境，也避免在树莓派装 PyTorch。
- 无 GPU 机器/纯数据开发：`uv sync` 默认 core + dev，不装 CUDA torch。
- **镜像一致性**：本机全局 `~/.config/uv/uv.toml` 曾配置 USTC 镜像，导致 `uv lock` 认为索引
  不一致而重新解析（曾 429）。`pyproject.toml` 已显式声明默认索引为 PyPI 官方源
  （`[[tool.uv.index]] name="pypi" default=true`），使本地 / CI / 服务器 lock 一致；
  国内镜像需求用临时环境变量覆盖（见 `docs/environment.md` §9，勿提交由此产生的 lock）。
- 体积预算：minimal `.venv` ≈1 GB；训练组合 Linux 下载 ≈3.4 GB、安装后约 7–9 GB
  （Windows torch wheel 自带 CUDA 运行库 ≈2.4 GB）。

## 5. 端侧部署服务器（deploy/server）

- 形态：本机 FastAPI 服务（默认 `127.0.0.1`，仅医生站浏览器访问）：
  - 前端单页（纯本地 HTML/CSS/JS，无 CDN、无外网请求，符合 §9.3 #10 离线合规）；
  - HTTP API：`POST /api/v1/jobs` 提交样本、`GET /api/v1/jobs/{id}` 查询结果、
    `GET /api/v1/jobs` 任务列表、`GET /health`、`GET /api/v1/schema`；
  - 后端 `asyncio.Queue` 排队 + worker 顺序执行；任务状态机 `queued/running/succeeded/failed`；
  - 预测器接口预留 ONNX 模型加载（`KITE_MODEL_DIR`）；无模型时进入 demo 模式并显式标记；
  - UI 固定展示「科研原型，不用于临床决策」声明。
- 与 `src/kite_drp/deploy/` 的分工：后者是训练机侧导出/量化代码，生成 `deploy/packages/` 部署包。
- 子模块策略：当前用独立 uv 项目实现"单独 Python 环境"；当出现以下情况再拆 git submodule：
  代码量/接口数量增长到需要独立发版、由不同团队维护、需要独立权限或镜像；
  拆分前保持 HTTP API 契约稳定（详见 ADR-0003）。
